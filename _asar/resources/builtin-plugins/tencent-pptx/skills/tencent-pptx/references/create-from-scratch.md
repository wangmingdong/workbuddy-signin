# 从零构建PPT的教程

## 制定任务计划

> **任务命名约束（强约束）**：本表仅为内部执行参考。在创建 TODO / 任务（TaskCreate）或向用户汇报进度时，**必须使用面向用户的术语**（如「内容大纲 / 风格设计 / 创建演示文稿 / 逐页制作 / 检查页面 / 交付」），**禁止暴露任何内部实现字眼**（如 `JSX`、`DSL`、`*.jsx`、`slidep-start`、`OOXML`、`success=true`、源码、组件文件名等）。

| Step | 职责（内部）                                                     | 产物（内部）                                     |
| ---- | ---------------------------------------------------------------- | ------------------------------------------------ |
| 1    | 信息收集（可选）                                                 | 背景资料 / 行业数据                              |
| 2    | 依据主题+信息构建PPT的叙述逻辑                                   | `STORY.md`                                       |
| 3    | 构建页面风格的设计逻辑                                           | `DESIGN.md`                                      |
| 4    | 启动 PPTX 服务（使用 `slidep-start` 创建 `.pptx` 并启动实时编译） | 目标 `.pptx` 已创建，实时编译服务已就绪          |
| 5    | 打开预览（使用 `present_files` 展示目标 `.pptx`）                 | 预览面板已打开，用户可实时观察生成进度            |
| 6    | 逐页生成 PPT（按大纲顺序写完全部页面）                           | 全部页面已生成                                   |
| 7    | 校验并修复页面                                                   | 全部页面校验通过                                 |
| 8    | 交付                                                             | 目标 `.pptx` 已在预览面板中呈现给用户            |


## 各步骤要求
### Step1：信息收集 （Optional）
当模型的信息不足、数据过时或需要行业标杆案例时，主动调用网络搜索的工具进行信息的收集，挖掘有深度、有据可查的实时内容。
判断信号：
- 主题涉及 `数字 / 市场 / 行业 / 新闻 / 分析` 等具有时效性的信息时 → 需要最新统计数据。
- 主题含`陌生缩写 / 专业术语 / 生僻词组` → 先查清楚。
- 用户明确要求 或 用户需要要“有说服力”但未提供素材 → 补充外部佐证。

若用户已提供完整参考材料（长文本、`.docx`、`.pdf` 等），本步可跳过或降级为只查陌生概念。

### Step2：构建叙事逻辑 （STORY.md）
阅读 [story-principle.md](story-principle.md)，最后生成一个STORY.md的文件。

### Step3：构建页面风格的逻辑 (DESIGN.md)

#### 风格匹配流程

收到用户需求后，执行以下推理判断是否命中预设风格：

**第一步：提取用户意图特征**
从用户 query 中识别：主题领域、目标受众、使用场合、调性倾向。

**第二步：与预设风格比对**

| 风格 | 核心调性 | 适用场景 |
| :--- | :--- | :--- |
| [学术风](references/designs/design-principle.academic.md) | 可信、证据驱动、蓝白克制 | 高校答辩、科研结题、教学课件（理工医）、学术会议、学科评估、临床/医学汇报、课题开题、实验室组会、科研申报 |
| [商务咨询](references/designs/design-principle.consulting.md) | 权威、数据密集、结构化分析 | 战略/行业研究、高管 review/董事会、投行/IPO 路演、咨询交付物、企业转型/组织变革、私募/风投/行研、尽职调查 |
| [红金政务风](references/designs/design-principle.redgold.md) | 庄重、红金热烈、中文优先 | 党政机关汇报、政务/公共部门、国企央企汇报、党课/学习宣讲、周年庆典/红色文化、表彰大会、纪检巡察 |

**第三步：做出判断**

判断标准：用户的场景是否**明确属于**上表某风格所服务的特定领域和受众。

- **命中**：用户场景明确落在某风格的适用场景内 → 使用该预设风格；
- **不命中**（默认路线）：用户场景不属于上述三类特定领域，或场景模糊/泛化/跨领域 → 走通用设计原则；

> ⚠️ **重要原则**：预设风格是为特定垂直领域定制的，不应泛化使用。大量常见场景（如：产品介绍、项目提案、工作总结、培训课件、技术分享、营销方案、团队介绍、述职报告、年终总结等）都应走通用设计原则，由 AI 根据具体需求自由设计。只有当用户场景**明确且典型地**属于学术科研、专业咨询、或党政红色这三个垂直领域时，才使用预设风格。

**判断示例**：
- "做一个硕士毕业答辩PPT" → 明确属于学术场景 → 命中学术风 ✅
- "做一个麦肯锡风格的行业分析" → 明确属于咨询场景 → 命中商务咨询 ✅
- "做一个党支部年度工作汇报" → 明确属于党政场景 → 命中红金政务风 ✅
- "帮我做个述职报告" → 职场通用场景，不属于上述三类特定领域 → 走通用 ✅
- "做一个产品发布会PPT" → 产品/营销场景 → 走通用 ✅
- "做一个季度工作总结" → 职场通用场景 → 走通用 ✅
- "做一个AI技术分享" → 技术/科普场景 → 走通用 ✅

#### 匹配后的执行

- **命中预设风格**：读取对应风格文件，结合用户实际需求设计PPT，**禁止额外生成DESIGN.md**，可以显式声明哪些颜色、字体等内容需要结合用户需求微调；
- **不命中（默认路线）**：读取通用[设计原则](references/design-principle.md)，结合用户实际需求生成DESIGN.md；


### Step4：启动pptx的渲染引擎
> **本步是硬约束**：进入逐页生成前，必须完成 `slidep-start` 创建目标 `.pptx` 。如下是运行要求：
>
> 运行 `${NODE_BIN_DIR}/slidep-start --project "项目根目录或工作目录" --filename "文件名称.pptx"`，创建并启动目标 `.pptx` 文件，同时启动将 `pages/*.jsx` 实时编译写入该 `.pptx` 的服务。若出现异常情况，例如之前已启动但目标 `.pptx` 为空、未正确生成或实时编译链路失效，可以重新运行 `slidep-start` 重新创建/启动目标文件与编译服务。
>
> **文件名命名约束**：`--filename` 指定的 `.pptx` 文件名默认使用中文（如 `"季度汇报.pptx"`、`"项目提案.pptx"`），只有在用户明确要求英文文件名时才使用英文。


### Step5：打开预览
> **本步是硬约束**：在开始逐页生成前，必须先调用 `present_files` 将目标 `.pptx` 文件在预览面板中打开，让用户可以实时观察后续页面的生成进度。
>
> ```
> present_files("项目目录/文件名称.pptx")
> ```
>
> 预览打开后即可进入下一步逐页生成。

### Step6：逐页生成 PPT（按大纲顺序）
> 动笔前的心智校准：每一页是一个 `.jsx` 文件，但**它不是 React**——这是一套受限 DSL，工程直接编译成 OOXML（.pptx）。把它当 HTML + 内联 CSS 来写。禁止引入 React 生态任何概念（`import` / `export` / `module` / hooks / state / 函数组件定义），文件最后一个表达式必须是 `<Slide>`。
>
> 动笔前必读：
> - `STORY.md` - 当前PPT的叙事逻辑
> - `DESIGN.md` — 当前 PPT 的设计稿（画布、配色、字号、布局、元素、密度）
> - 相关组件规范 — 本页用到哪个组件，就读取 `references/component-*.md` 中对应文档
>
> **动笔前禁读**：本项目目录之外的任何 PPT 项目源码（详见 §Step 4 设计依据封闭原则）。本页 JSX 的全部依据应来自 `DESIGN.md` + 命中分支 `design-principle.<id>.md` + `component-*.md`，不得"借鉴"历史项目的 jsx 写法或视觉选择。
>
> 严禁仅靠记忆动笔。

约束如下：
- 充分结合 `STORY.md` 和 `DESIGN.md`，按照大纲顺序从第 1 页生成到第 N 页，一次写完全部页面；
- 配图前置：若涉及到生图内容，必须在写内容前完成生图流程，**并且必须使用 `read_image` 工具对生成的图片进行视觉检查，确认图片清晰、无水印且符合上下文后方可使用**；
- 写入页面源文件： write_to_file 到 pages/slide_{NN}_{desc}.jsx；
- 动笔自检（每页提交前 10 条硬约束，逐项确认；任意不通过 → 当页返工） 
  - 母版区齐全：默认三区（A 标题块 0–120px / B 内容区 120–660px / C 页脚条 660–720px 含右下页码 NN/TOTAL）； 
  - 标题块右侧不得塞装饰小图（200×70 这种），全篇位置严格一致； 
  - 本页 L1 主视觉占 B 区面积 ≥ DESIGN.md 规定（默认 30%）；不得用 L3 角标顶替 L1 
  - 仅使用项目 DESIGN.md 列出的 ≤ 4 种 hex 与 ≤ 2 套字体家族 
  - 与上一页版式不重复；本页留白比例 ≤ DESIGN.md 上限（常规页 ≤ 35%） 
  - 本页有 ≥ 1 个视觉锚点（≥ 44px 元素 或 ≥ 40% B 区面积的图）；如无 → 必须补充巨型数字/大图/大色块 
  - 本页与上一页视觉重量有显著差异（最大元素面积比 > 1.5:1 或版式结构明显不同）；连续 ≥ 2 页等宽卡片横排 → 返工 
  - 本页色彩分配符合 DESIGN.md 页面映射表：强调色只出现在焦点元素上，主色/辅色/强调色面积比合规 
  - 本页的 role 与 STORY.md 一致：hero 页必须有 ≥ 40% B 区主视觉或 ≥ 48px 锚点数字；supporting 页不得使用 hero 级视觉投入


### Step7：页面校验与修复
所有页面写完后，一次性跑全量校验。如果返回内容中包含`success: false`, 请根据工具的返回结果去修复有问题的页面。
最终必须要确保所有页面语法正确。

```bash
for f in pages/slide_*.jsx; do ${NODE_BIN_DIR}/slidep-validate "$f" --project $(pwd); done
```

### Step8：PPTX 交付
全部页面校验通过后，向用户交付最终成果：

- 使用面向用户的语言（禁用 `JSX` / `slidep-*` / `OOXML` 等内部字眼）简要说明本次 PPT 的主题、页数与风格要点，提示用户可在预览面板中查看。


## 生成后的编辑（后续行为指导）

**PPTX 交付后，用户提出修改需求时，所有后续的内容修改/编辑通过阅读使用 `tencent-local-office-edit` SKILL完成。禁止回退到 JSX 源文件进行修改。**
